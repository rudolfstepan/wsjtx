WSJT-X OE3SRO Custom

build by OE3SRO · Windows x64 · Deutsch / English

Windows-Paket mit integrierter PSK-Reporter-Liste, Anrufhilfen, FT2 und experimentellem REIST16. Die Paketversion und der Quellstand stehen in build-info.json im Hauptordner.

REIST16 — neue experimentelle Betriebsart

Aktuell: QSO/2 mit 12,8 s Signalzeit, LDPC und 15-s-Slots. Beide Gegenstellen aktualisieren. Neues Profil und Rauschmessung. Der folgende Hardwareversuch gehört zum bisherigen QSO/1.

Mode → REIST16 aktiviert den neuen CQ-/QSO-Modus mit festen 15-Sekunden-Slots. Er verwendet Soundkarten-Audio, beispielsweise Yaesu USB-Audio. Eine passende Frequenz selbst einstellen. start-pluto.bat startet die Pluto-Bridge und die zweite WSJT-X-Instanz mit eigenem Profil. Pluto einrichten. Diese Verbindung benötigt keinen zusätzlichen Codec-Flow. Profilvertrag und Prüfstand. Der Benutzer-Screenshot belegt beidseitige Dekodierung zwischen Yaesu OE3SRO und Pluto OE3SRO/P auf 432,500 MHz, mit Auto Seq bis RR73 und anschließendem 73-Senden. Keine gemessene Empfangsschwelle. Ausführlicher Versuch und Grenzen.

Deutsch — Installation und erster Start

  1. Das ZIP mit windows-x64 im Namen von der GitHub-Releases-Seite herunterladen.
  2. Das gesamte ZIP in einen eigenen Ordner entpacken. bin, share und docs zusammen behalten.
  3. Start-WSJT-X.bat per Doppelklick öffnen. Eine separate Installation der mitgelieferten DLLs ist nicht erforderlich.
  4. Beim ersten Start unter Settings eigenes Rufzeichen, Locator, Funkgerät/CAT und Audioeingang/-ausgang einrichten.
  5. Gewünschten Modus und eine passende Arbeitsfrequenz auswählen, dann Empfang mit Monitor starten.

Der Launcher verwendet das Profil Custom. Ein vorhandenes Custom-Profil einschließlich Einstellungen und Logbuch wird weiterverwendet. Das Paket importiert keine Einstellungen aus einer anderen WSJT-X-Installation. Eine vorherige Custom-Version vor dem Start normal beenden.

PSK Reporter — Wer hört mich?

View → PSK Reporter — Who hears me? öffnet die Empfängerliste. Abfragen verwenden Rufzeichen, Modus und Band aus dem laufenden Hauptfenster. Angezeigt werden Empfänger, die dein Signal in den letzten 30 Minuten gemeldet haben.

  • Current band and mode: gesamtes aktuelles Band im aktuell eingestellten Modus (Vorgabe).
  • Current frequency and mode: Anzeige auf Dialfrequenz bis +5 kHz beschränken.
  • Refresh: neue Abfrage frühestens alle fünf Minuten. Der Countdown zeigt die Wartezeit; die Automatik arbeitet bei geöffneter Liste.
  • Suche nach Rufzeichen/Locator, Favoriten, Logbuchfilter und Empfangsalter 5/15/30 Minuten helfen bei der Auswahl.

Meldungen treffen verzögert ein. Ohne gemeldeten Empfang des eigenen Signals bleibt die Liste leer. Bei Modus- oder Frequenzwechsel werden alte Einträge entfernt; der nächste erlaubte Abruf verwendet den neuen Betriebskontext. Abfragefehler stehen unter der Tabelle und erhalten vorhandene Meldungen bis zum Ablauf.

Station anrufen und TX stoppen

Call station oder Doppelklick auf eine Station übernimmt Rufzeichen und Locator, wählt Tx1 und aktiviert Enable Tx: Die erste Standardnachricht wird im nächsten eingestellten TX-Zeitfenster gesendet. Eigene TX-Frequenz und TX-Sequenz bleiben maßgeblich. Direkte Anrufe und türkis unterstrichene Band-Activity-Markierungen verwenden nur Meldungen im aktuellen Arbeitsbereich (Dialfrequenz bis +5 kHz).

Repeat last und Call recent wiederholen einen früheren Anruf bei passendem Rufzeichen/Modus/Frequenzkontext. Call next startet pro Klick einen Anruf zur nächsten passenden sichtbaren Station. Halt Tx stoppt TX wie im Hauptfenster. Favoriten und die letzten 20 Anrufe bleiben im Custom-Profil gespeichert.

FT8-/FT4-/FT2-Sendediagnose und Mehrkernbetrieb

View → TX quality — FT8 / FT4 / FT2 zeigt Audiofrequenz nach Split, Ausgangsdämpfung, Audiopuffer, übersprungene Samples bei verspätetem Start und während TX optional ALC über CAT. ALC ist keine Verzerrungsmessung. Der Dialog bietet auch den vorhandenen parallelen Decoder mit Auto oder 1–12 Workern für FT8. FT4/FT2 nutzen automatisch bis zu acht Worker für größere Synchronisationsraster. Die Anzeigen messen weder USB-Latenz noch das abgestrahlte Signal.

FT2 auswählen

Mode → FT2 aktiviert den experimentellen Modus mit 3,75-Sekunden-Perioden. Fehlende FT2-Frequenzvorgaben werden einmalig ergänzt. Eigene Frequenzen lassen sich unter Settings → Frequencies eintragen. FT2 beruht auf der GPLv3-Implementierung von DG2YCB / WSJT-X Improved (heute WS Suite).

Persönliche DX-Zeitfenster und Abfragepausen

Personal DX windows im PSK-Reporter-Fenster sammelt lokal Meldungen des eigenen Signals nach DXCC-Land, Band, UTC-Stunde und Monat. Die Rangfolge verwendet unterschiedliche Empfangstage und Empfänger-Tage; wiederholte Abfragen zählen denselben Empfänger pro Datum/Stunde einmal. Rufzeichen, Modus und Stations-/Antennenprofile bleiben getrennt.

Next 24 hours (UTC) zeigt die nächste Wiederkehr historischer Stundenfenster; Now bedeutet, dass die Stunde bereits läuft. Filter für Monat, Land/Band, Mindestzahl an Empfangstagen sowie gesamte oder letzte 90/365 UTC-Tage und erste/letzte Beobachtung helfen, die Datenbasis einzuschätzen. Das ist keine Live-Prognose oder QSO-Wahrscheinlichkeit.

Die Daten wachsen mit regulären Abfragen bei geöffnetem PSK-Fenster. Keine historischen Rückabfragen. Nach Änderungen an Antenne, Standort oder Leistung einen neuen Stations-/Antennenprofilnamen eingeben und das Feld verlassen.

Bei HTTP 429/503 steigt die Pause von zehn bis auf 60 Minuten; längere Servervorgaben haben Vorrang. Der Countdown und die Pause bleiben über Neustarts und Profilwechsel derselben Konfigurationsdatei erhalten. Die Browserkarte kann unabhängig davon funktionieren. Fremde Programme/Browser werden nicht koordiniert.

REIST16 — new experimental mode

Current profile: QSO/2, 12.8 s LDPC-protected frames in 15-second slots. Update both endpoints. Profile and noise measurements. The earlier RF screenshot demonstrates QSO/1.

Mode → REIST16 selects the experimental CQ/QSO mode with fixed 15-second UTC slots. Use a frequency agreed with the peer. start-pluto.bat launches the Pluto bridge and a separate WSJT-X profile; see Pluto setup and the protocol and test notes. The user screenshot above confirms two-way decoding and Auto Seq through RR73, followed by Pluto transmitting 73. Final 73 reception is not visible; sensitivity remains unmeasured. Test details.

English — Installation and first launch

  1. Download the ZIP named windows-x64 from GitHub Releases.
  2. Extract the entire ZIP into its own folder. Keep bin, share, and docs together.
  3. Double-click Start-WSJT-X.bat. The required DLLs are bundled.
  4. On first launch, configure your callsign, locator, radio/CAT, and audio input/output in Settings.
  5. Select the desired mode and an appropriate working frequency, then enable Monitor to receive.

The launcher uses the Custom profile. Existing Custom settings and logs are reused. No settings are imported from another WSJT-X installation. Close an earlier Custom instance normally before launching.

PSK Reporter — Who hears me?

Open View → PSK Reporter — Who hears me?. Queries read callsign, mode, and band directly from the running main window. The list shows receivers reporting your signal during the past 30 minutes.

  • Current band and mode: the current mode across the current band (default).
  • Current frequency and mode: limit the display to dial frequency through +5 kHz.
  • Refresh: at least five minutes between requests. The countdown shows the remaining wait; automatic refresh runs while the list is open.
  • Use callsign/grid search, favorites, logbook filters, and 5/15/30-minute report age to select stations.

Reports are delayed. Without reports of your own signal, the list remains empty. Mode/frequency changes clear old entries; the next allowed request uses the new context. Request errors appear below the table and preserve existing reports until they expire.

Personal DX windows and query cooldown

Personal DX windows collects local observations by DXCC country, band, UTC hour and month, separated by callsign, mode and named station/antenna setup. Rank by distinct reception days and receiver-days without duplicate polling counts. Next 24 hours (UTC) shows recurring historical hourly windows, not a live propagation forecast or QSO probability.

Filter by month, country/band, minimum reception days and all/90/365-day history. First/last observation dates show sample age. Collection uses regular queries while the PSK window is open, without backfill. Enter a new setup name after antenna/location/power changes.

HTTP 429/503 triggers increasing backoff from ten to 60 minutes, respecting longer server instructions. Cooldowns survive restarts and profile changes using the same settings file. The browser map may remain available; other applications and browser requests are not coordinated.

Calling a station and stopping TX

Call station or double-click fills callsign and locator, selects Tx1, and turns on Enable Tx. The first standard message is sent in the next configured TX period, using your TX frequency and sequence. Direct calls and turquoise underlined Band Activity markers require reports in the current working range (dial frequency through +5 kHz).

Repeat last and Call recent repeat a previous call when operator/mode/frequency context matches. Call next starts one call per click to the next suitable visible station. Halt Tx stops TX like the main window. Favorites and the last 20 calls are saved in the Custom profile.

FT8 / FT4 / FT2 transmit diagnostics and multiple cores

View → TX quality — FT8 / FT4 / FT2 shows split-adjusted audio frequency, attenuation, buffer information, samples skipped at late starts and optional CAT ALC during TX. ALC is not a distortion measurement. The dialog also controls the existing FT8 parallel decoder with Auto or 1–12 workers. FT4/FT2 automatically use up to eight workers for larger synchronization grids. These readings do not measure USB latency or the radiated signal.

Selecting FT2

Mode → FT2 enables the experimental mode with 3.75-second periods. Missing FT2 frequency defaults are added once; enter your own frequencies under Settings → Frequencies. FT2 adapts the GPLv3 implementation by DG2YCB / WSJT-X Improved, now WS Suite.
