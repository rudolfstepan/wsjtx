# WSJT-X OE3SRO Custom — Windows-Release 3.0.2-oe3sro.3

**Windows x64 · build by OE3SRO · Basis WSJT-X 3.0.2-devel**

## Download und Start

Das **windows-x64.zip** vollständig entpacken und **Start-WSJT-X.bat** starten.
Es enthält Anwendung, Decoder, Qt/OpenSSL-DLLs, Hamlib-Tools, Stationsdaten
und die deutsche/englische Anleitung unter **docs/index.html**.
Die Anleitung ist zusätzlich als **documentation.zip** verfügbar.
Beide ZIPs haben SHA256-Dateien; `build-info.json` nennt Quellcommit und EXE-Hash.
Vorhandene **WSJT-X - Custom**-Einstellungen bleiben erhalten. Persönliche
Konfigurationen und Logbücher werden nicht mitgeliefert.

## Neu gegenüber 3.0.2-oe3sro.2

- **Personal DX windows** im PSK-Reporter-Fenster sammelt Empfangsmeldungen
  des eigenen Signals lokal nach DXCC-Land, Band, UTC-Stunde und Monat.
  Rufzeichen, Modus und benennbare Stations-/Antennenprofile bleiben getrennt.
- Rangfolge nach unterschiedlichen Empfangstagen und Empfänger-Tagen;
  wiederholte Abfragen zählen denselben Empfänger pro UTC-Datum/Stunde einmal.
- **Next 24 hours (UTC)** zeigt die nächste Wiederkehr historischer
  Stundenfenster. Monats-/Jahreswechsel und laufende Fenster (**Now**) werden
  berücksichtigt. Filter: Land/Band, Monat, Mindestzahl an Empfangstagen,
  gesamte Historie oder letzte 90/365 UTC-Tage. Erste/letzte Beobachtung sichtbar.
- **HTTP 429/503:** steigende Wartezeit (10/20/40/60 Minuten als Rückfall),
  längeres Server-`Retry-After` beachten. Abfragepausen überleben Neustarts
  und gelten für Profile/Instanzen derselben Konfigurationsdatei.
  Verständlicher Status und Countdown statt langer Fehler-URL.

Die Statistik beginnt mit den regulären Abfragen bei geöffnetem PSK-Fenster;
keine historischen Rückabfragen. Positive Beobachtungen sind keine
QSO-Erfolgswahrscheinlichkeiten oder Live-Ausbreitungsprognosen. Eigene
Sendeaktivität, Leistung und Empfängeraktivität beeinflussen die Datenbasis.
Bei Anlagenänderungen einen neuen Stations-/Antennenprofilnamen vergeben.
Eine funktionierende Browserkarte schließt eine Begrenzung der XML-Abfrage
nicht aus. Andere Programme/Browser werden durch die lokale Pause nicht erfasst.

**Call station aktiviert TX. FT2 bleibt experimentell.**

## Build und Prüfungen

GitHub Actions baut aus **oe3sro-v3.0.2-3** und veröffentlicht die ZIPs erst nach
erfolgreichen PSK-/Statistik-, Logbuch-/UDP-, nativen Codec-/TX-Audio-, FT2-/FT4-,
SMP- und Paketlaufzeitprüfungen. Die neuen Regressionstests prüfen UTC-Grenzen,
Persistenz, Profiltrennung, Filter, `Retry-After` und HTTP-429-Wartezeiten mit
einem lokalen Testserver. Kein automatisierter Funkbetrieb.

## English

Extract the **windows-x64.zip** completely and launch **Start-WSJT-X.bat**.
The package includes executables, runtime libraries, station data and German/
English documentation at **docs/index.html**. Documentation is also available
separately. Both ZIPs have SHA256 files; `build-info.json` identifies the source
commit and EXE checksum. Existing Custom settings are reused; personal settings
and logs are not distributed.

New since 3.0.2-oe3sro.2:

- **Personal DX windows:** local reception history by DXCC country, band,
  UTC hour and month, separated by own callsign, mode and named station setup.
- Rank by distinct reception days and receiver-days without duplicate polling
  counts. **Next 24 hours (UTC)** orders recurring historical hourly windows,
  including month/year transitions and ongoing windows (**Now**).
- Filter country/band, month, minimum reception days and all/90/365-day history.
  First and last observation dates show the sample age.
- **HTTP 429/503:** increasing fallback backoff of 10/20/40/60 minutes, honoring
  a longer server `Retry-After`. Query cooldown survives restarts and is shared
  by profiles/instances using the same settings file. Clear status and countdown.

Collection uses regular queries while the PSK window is open, without historical
backfill. Positive counts are neither QSO probabilities nor live propagation
forecasts. Activity and power bias observations. Use a new setup name after
antenna/location/power changes. Browser availability does not rule out XML query
rate limiting; other applications and browser requests are not coordinated.

**Call station enables TX. FT2 remains experimental.** GitHub Actions builds
the tagged source and publishes after integration, codec, TX audio, SMP and
standalone runtime checks. No automated RF transmissions are performed.
